# Wix Headless backend adapter (`lib/wix/`)

Moved out of `AGENTS.md` section 6, item 7, verbatim, so the instruction file stays short. The rules below are binding exactly as before; `AGENTS.md` keeps the summary and links here.

7. **Wix Headless Backend Adapter (`lib/wix/`)**:
   - Target architecture: this Next.js frontend + Wix Headless business backend ([`docs/WIX_HEADLESS_ARCHITECTURE.md`](docs/WIX_HEADLESS_ARCHITECTURE.md)). The only writable Wix target is the **"SimDream-Staging"** Headless site (metasite `317b0c6d-6608-499a-bb3c-b1c37650e460`); the live Editor site on simdream.co.il and the retired `4c5e1c7a-163c-48ce-8278-cdc42e4deed4` site are never written to from this repo.
   - Wix has two public-client boundaries under [`lib/wix/`](lib/wix/index.ts): [`client.ts`](lib/wix/client.ts) holds the process-wide anonymous-visitor `@wix/sdk` client, while [`member-client.ts`](lib/wix/member-client.ts) is browser-only and holds a tab-scoped member OAuth session. Both use only `NEXT_PUBLIC_WIX_CLIENT_ID`; Bookings is called over REST via `fetchWithAuth` (`@wix/bookings` is not installed — its React 18 peer dependency conflicts with React 19). `WIX_SITE_ID` is informational. No client secret, API key or PayPlus credential ever enters the repo or the browser.
   - [`lib/wix/catalog.ts`](lib/wix/catalog.ts) maps 9 of the 10 `SIMULATOR_PACKAGES` ids to their Wix Bookings service ids, while `pkg-grand-120` stays in `PENDING_WIX_PACKAGE_IDS` until provisioned and wired via `WIX_SERVICE_ID_GRAND_120` / `NEXT_PUBLIC_WIX_SERVICE_ID_GRAND_120` (and native add-on group IDs are added to `GROUP_IDS_BY_PACKAGE`); `reconcileCatalog()` must report 0 mismatches for mapped services. Run `npm run wix:smoke` after touching the catalog or the Wix services (it lists services, reconciles, and reads tomorrow's bookable slots).
   - **Wix-mode availability re-anchors on the real bookings** ([`lib/wix/availability-adapter.ts`](lib/wix/availability-adapter.ts), [`lib/wix/wix-blocked-bookings.ts`](lib/wix/wix-blocked-bookings.ts)): Wix lists every start (on its 5-minute raster) that clears the existing bookings and the 15-minute turnaround, so the holes in that list are the bookings. `wixBlockedBookings()` turns each hole back into a reserved interval and the Kantorovich engine, run with `minSellableGaps`, offers the first start 15 minutes after a booking (14:05 end → 14:20) and the latest start before the next one, besides the normal cadence; a start is refused when it strands a gap shorter than the shortest 45-minute reservation, except a flush closing-tail departure (`gapBefore === 0` at `nextBoundary === config.closeMinutes` with `gapAfter < 45`, recovering e.g. Saturday `22:00` 90m). `/api/slots` and `resolveWixBookingCheckout()` call the same `getWixBackedKantorovichSlots()`, so the checkout accepts exactly the departures the calendar shows; when a recreational promotional tier bump-up (`30m→60m`, `45m/60m→90m`, `…→120m`) activates, `useBookingSchedule` switches `/api/slots` to the upgraded duration's own schedule grid (`resolveScheduleDurationMinutes()`), snapping to the nearest compatible departure if needed (`findNearestCompatibleSlot()`) and surfacing `SlotAdjustmentBanner` with a one-click "Change time" action so upgraded bookings never fragment shorter grids, while `WixDraftPrepareError` (`lib/booking/client/wix-checkout-cart.ts`) surfaces real `409`/`503` departure errors directly instead of blaming a coupon or gift card. A day with no booking stays exactly the fixed grid. **While the Bookings Pricing provider is active only fixed-grid starts are offered**, because `strictWixGridDepartureFor()` accepts only the package's empty-day grid and refuses every other start (`off-grid-departure`); extend the provider before enabling it where re-anchored starts matter. `tests/unit/wix-dynamic-availability.test.ts` pins the 24 Nov and Saturday closing-tail examples.
   - **Time-adding add-ons are native Wix Bookings add-ons on the four consumer services** ([`lib/wix/native-addons.ts`](lib/wix/native-addons.ts)): `resolveWixBookingCheckout()` asks Time Slots V2 with `customerChoices.addOnIds`, so Wix returns the slot as long as the whole mission; the browser revalidates it with the same choices and creates the booking with that end time and `bookedAddOns`, so the Wix calendar blocks the full period, not only the base session. Wix prices the add-ons as modifiers of the booking line item in Cart V2 (verified on staging: ₪690 + ₪200 = ₪890), so they are **not** added as Stores products any more (`WIX_ADDON_PRODUCT_IDS` remains only for an add-on with no native mapping) and the Bookings Pricing provider keeps returning the base price only. The server fails closed (503) when the minutes Wix adds differ from `FLIGHT_ADDONS`; `tests/unit/wix-native-addons.test.ts` keeps the id map and the registry in step. A subscription redemption opens Wix's hosted checkout with the base slot, so it still only checks the longer duration (`{ nativeAddOns: false }`). Every production service needs the same add-on groups before this ships there; the live site is never written to from this repo.
   - Source mappings and browser checkout code do **not** prove that a Wix service, Store product, pricing plan, payment provider, or pricing extension is configured or published. Treat `npm run wix:smoke`, `npm run wix:readiness`, and a recorded staging purchase as separate evidence. The readiness script resolves all six subscription passes, including the PRO IDs (`WIX_PLAN_ID_PRO_3X90`, `WIX_PLAN_ID_PRO_5X60`), against the target Wix site.
   - **Wix Blog reads stay locale-bound** ([`lib/wix/blog.ts`](../../lib/wix/blog.ts)): Blog V3 Query Posts requests place filtering and paging under the API's `query` envelope. A post lookup combines `slug: { $hasSome: [slug] }` with `language: { $eq: requestedLanguage }`, because the Blog API does not support `$eq` for `slug`; the adapter rejects a response whose declared language does not match and falls back to the local authoritative corpus. This prevents an ignored or stale remote filter from rendering English navigation or structured data on a Hebrew blog route. [`tests/unit/wix-blog.test.ts`](../../tests/unit/wix-blog.test.ts) pins both the wire shape and mismatched-language fallback.
   - The availability adapter alone does not bind Wix bookings to the local zero-waste grid, because the browser calls Wix Create Booking itself; the Bookings Pricing provider does, refusing to price any mapped booking whose start is not on the package's empty-day grid (`isOnStrictWixGrid()` / `strictWixGridDepartureFor()` in [`lib/wix/booking-grid-policy.ts`](lib/wix/booking-grid-policy.ts), returning `off-grid-departure`; `resolveWixBookingCheckout()` validates via `getWixBackedKantorovichSlots()`, which switches to the empty-day grid while that provider is active), and `npm run wix:readiness` prints `Scheduling grid enforcement: provider` when that provider is fully configured in the environment it runs in, otherwise `none` plus a WARN while the adapter flag is on ([grid enforcement](docs/WIX_BIRTHDAY_PRICING_PROVIDER.md#grid-enforcement)). The complete 37-variable deployment environment inventory lives in [`.env.example`](.env.example) and [`GENESIS.md`](GENESIS.md).
   - Agent know-how for Wix work comes from `npx skills add wix/skills` (installed under `.agents/skills/`, git-ignored) plus the Wix MCP connector; confirm every endpoint from the docs, never from memory.

## Worker toolchain and the cookie bundle

- `@opennextjs/cloudflare` is pinned to exactly 1.20.16 (with `@opennextjs/aws` 4.1.15). 1.20.18 (with aws 4.2.0) added an esbuild plugin to the middleware bundle that emitted `import_cookie = __toESM(require_dist())` without the node-mode flag, so `import_cookie.default` was undefined and every request carrying a Cookie header answered HTTP 500 ("Cannot read properties of undefined (reading 'parse')") in `v1.31.2` to `v1.32.0`. Cookie-less requests, curl probes and the old smoke checks stayed green; localhost runs on Node and never shows it.
- `npm run wix:build` fails on that bundle: `scripts/prepare-wix-worker.mjs` runs `findBrokenCookieImports` (`scripts/wix-worker-guards.mjs`, test `tests/unit/wix-worker-guards.test.ts`) over `.open-next/middleware/handler.mjs` before wrangler minifies it.
- Dependabot ignores later `@opennextjs/cloudflare` versions. Move past 1.20.16 only when a release passes `npm run wix:build` and a cookie request on the built Worker (`wrangler dev` with a scratch config, then `curl -H 'Cookie: a=1'`), then drop the `@node-minify/core` `glob` override in `package.json` if the audit no longer needs it.
- Verified on Node 24.22.1 and Node 26: lint, `docs:verify`, audit, `wix:build` (worker about 10.16 MiB of 14), the cookie request, `test:quick`.

## Outbound read deadlines

`lib/http/timeouts.ts` owns the deadlines. `wixPost(url, body, { timeoutMs })` is opt-in: the read callers (blog, plans, gift-card products, Bookings services and availability) pass `UPSTREAM_READ_TIMEOUT_MS` (8 s), and a request that does not answer becomes a 504 `WixApiError`, handled like any other upstream failure. One availability query across its cursor pages has a 20 s total deadline. The member-token check (`lib/wix/member-auth.ts`, on every authenticated checkout) has 5 s and treats a timeout as unauthenticated; the member calendar has 8 s. **Calls that create something carry no deadline** (Wix cart creation, the cart checkout URL, Stripe sessions): an abort on the client could leave an orphan cart or session. `tests/unit/outbound-timeouts.test.ts` pins which calls have a deadline and that a write has none.

## Blog queries

The post lookup filters by `slug $eq` and `language $eq`; the list by `language $eq`. Wix rejects `$hasSome` on a slug with HTTP 400 although its reference lists it, and the resolver used to swallow that and serve every translation in Hebrew. Every fallback to the local articles now logs a warning. Full contract, history and guards: `docs/modules/blog-language.md`.
