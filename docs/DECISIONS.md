# Decisions

The project's memory between agent sessions. Every new session reads this file together with `docs/PROJECT_STATE.md`. Record a decision here the moment it is made, and append unfinished work to Open items. Keep entries short, dated and true: when an item is resolved, move it to Settled with the PR or commit; when a rule turns out wrong, delete it.

Standing product and architecture rules (pricing, scheduling, i18n, Wix read-only production, telemetry in LTR) live in `AGENTS.md`; this table records dated decisions and why they were taken.

## Working rules learned the hard way

- **A reboot loses the chat and `/private/tmp`.** Git and GitHub survive. Push a draft PR before a long step, and put decisions and the next step in `docs/PROJECT_STATE.md` and this file. A new session begins with `npm run status`, so nothing depends on anyone remembering where things were.
- **Verify staging with Playwright in Docker, against the staging URL only.** At this stage the only URL to test is `https://headless-ciwstxzqhgf-hatan4ik-1408.wix-site-host.com` (owner's instruction, 2026-11-25); the staging runners refuse every other host. After a publish, run `npm run test:staging:content:docker` (read-only, the pinned Playwright image, refuses `simdream.co.il`). Do not drive the owner's own browser profile with the Chrome extension: it carries their cookies and localStorage, is not reproducible, and froze a tab of theirs. The sandbox Playwright projects cannot reach staging, which is why this suite exists.
- **A `<Suspense>` boundary around a large client subtree streams.** Text above React's 12.8 kB progressive chunk size is always sent as a fallback plus a hidden segment swapped in by `requestAnimationFrame`; if hydration wins the race, both copies sit in the DOM and every id is duplicated. For content that must be in the first HTML (the Hebrew legal text), render it in an async server component and pass it down as a slot. Test with `requestAnimationFrame` delayed (`tests/usability/legal-duplicate-ids.spec.ts`).
- **Wix docs are not the API.** A filter operator listed in a Wix reference can still be rejected by the live API (`$hasSome` on a post `slug`, HTTP 400, 2026-11-24). Before changing a Wix query, run the exact body against the live API as an anonymous visitor (the OAuth client id is the public `appId` in `wix.config.json`; read-only), and test the resolver against it for every language, not only with a mocked `wixPost`. A silent `catch` that falls back to local data hides such a failure for hours; this one now logs.
- **A retrying Playwright assertion can wait out the thing it checks.** `expect(locator).not.toHaveAttribute(...)` polls for 10 s, so it passed against code that set `data-language-pending` for 3 s (2026-11-25). Read a state that a timer clears once, with `page.evaluate`, at the moment it matters; prove every new browser spec red on the old build before trusting its green. The shared fixture also seeds `simdream_lang=en`, so a "first-time visitor" test must remove it. A journey for a Hebrew or first-time visitor now sees the server HTML before hydration (the hidden body used to hold Playwright back until then): it must `waitUntilInteractive(control)` (`tests/e2e/pages/hydration.ts`) on the control it types into, because a form hydrates after the layout and text typed into a control React does not own yet is reset when it takes over (seen in CI as an empty first field); and `waitUntilPageHydrated(page)` before measuring a page and ending while its own requests are in flight (WebKit reports those cancelled fetches as uncaught exceptions). CI caught this in three tests (`offers.spec.ts`, `refund-form.spec.ts`, the voucher matrix in `booking-multilang-addons.spec.ts`); the last one only on slow runners, and a first fix that waited on the layout was not enough, the failure screenshot showed the real cause.
- **Branches.** Cut `devel/<topic>` from a freshly fetched `origin/main`, finish with a PR, never work on `main` (other teams use it). `.claude/hooks/block-main-commit.sh` blocks committing on `main`, and `.claude/settings.json` denies the common push-to-main forms (`git push origin main`, `+main`, `HEAD:main`, `refs/heads/main`, `-u`/`--set-upstream origin main`) and force pushes including `--force-with-lease`; prefix patterns cannot catch every spelling (a different remote name, options placed before `origin`), so branch protection is the real backstop. The same two rules also hold outside Claude Code: tracked git hooks in `.githooks/` (`pre-commit` refuses a commit on `main` or with a staged `.env*` file other than `.env.example`; `pre-push` refuses a push to `refs/heads/main`) are switched on by `npm install` (the `prepare` script sets `core.hooksPath`); `--no-verify` is the deliberate escape hatch. A Bash command that merely mentions that commit command is blocked by the Claude Code hook while on `main`, so cut the branch in its own command first.
- **Measure the Worker in a clean room, not in a long-lived checkout.** A checkout's `node_modules` can drift from the lockfile (2026-11-25: `@opennextjs/cloudflare` 1.20.18 installed against the 1.20.16 pin, Node 26 against `engines` `>=24.22.1 <25`, only the Linux `@ast-grep` binding), and the cookie guard in `npm run wix:build` then refuses the build for a reason that is not the change. Reproduce CI: `git archive HEAD` into a scratch directory, then `docker run -v "$PWD:/work" -w /work node:24.22.3-bookworm bash -c 'npm ci && npm run wix:build'` (about 5 minutes); `next build` also type-checks `tests/`, which Vitest does not.
- **Test target.** Probe the new app on the staging Wix headless host `https://headless-ciwstxzqhgf-hatan4ik-1408.wix-site-host.com`, never on `www.simdream.co.il` (still the old Editor site, where `/book`, `/pro` and `/experiences` return 404). Name the host in every finding.
- **Go slowly against Wix.** Wix and Cloudflare answer HTTP 429 after a few hundred requests a minute; send requests one at a time, and discard any run that shows 429s. On tablet profiles use real `tap()` calls followed by `waitForURL` (Next client navigation never fires `load`). Never grep page bodies for "not found": Next embeds its not-found template in every page.
- **Concurrent sessions.** Another agent may edit or auto-commit in this checkout and replace `.next-test`. Before blaming code, check `ls .next-test/BUILD_ID`, `git status` and `uptime`; run `npm run typecheck` before `npm run test:build`; never revert another session's in-progress files.
- **Playwright port trap.** `webServer` has `reuseExistingServer: !CI`, so a stale `next-server` on `PW_PORT` (default 3100) silently serves an old build. Check `lsof -nP -iTCP:3100 -sTCP:LISTEN` and run with a free `PW_PORT`.
- **Release pipeline.**
  - A release PR that fails `No successful main Verify run attests parent <sha>` is a race: wait for main's Verify, then `gh run rerun <run id> --failed`.
  - CodeQL and "Clean merge with base" on a Release Please PR park in `action_required`; approve them with `gh api --method POST repos/hatan4ik/simdream-website/actions/runs/<id>/approve`. Production approval is never allowed.
  - A merge of main into a PR branch made on GitHub leaves the Genesis fingerprint stale: re-check the `GENESIS.md` hunk, then `npm run docs:genesis:stamp`.
  - Runs with zero jobs and `startup_failure` mean a GitHub incident: check githubstatus.com before touching workflows.
  - Branch protection has `enforce_admins: true` and 14 required checks. Never weaken it.
- **Visual baselines without Docker.** Refresh Linux baselines from the failing CI shard's artifact (`gh run download <run> -n results-web-quality-shard-N`, copy `*-actual.png` to `<name>-visual-linux.png`) after the diff image shows only the intended change; darwin ones with a local `.next-test` build and `--update-snapshots=changed`. Any `/pro` change needs the four `pro-{brand,cockpit}-{en,he}-visual-linux.png` refreshed.
- **Wix rollback workflow.** `Roll back Wix production` could only restore the tag at the tip of `main`: its ancestry check ran after `git fetch origin main --depth=1`, which made the clone shallow (found 2026-11-24 when a rollback to `v1.31.2` failed in "Validate the rollback target"). Fixed on `devel/fix-wix-rollback-ancestry` by fetching `main` without a depth. The workflow runs on the `wix-production` environment, which targets the staging Headless site and needs the owner's approval in GitHub. The Wix CLI refuses a release comment over 250 characters, and the comment is `rollback to <tag> (<sha>): <reason>`, so keep the reason under about 150 characters.
- **Tests with a fixed date.** The slot engine closes departures that have already left on today's date, so a test that hard-codes a date and reads the real clock passes before the first slot of that day and fails after it (`wix-dynamic-availability.test.ts` broke `main`'s Verify at 16:21 Israel time on its own DATE, 2026-11-24, and would have failed on every run afterwards). Pin the clock with `vi.useFakeTimers({ toFake: ['Date'] })` and `vi.setSystemTime(...)` in a `beforeEach`: `tests/support/vitest.setup.ts` restores real timers after every test, so a `beforeAll` pin only lasts for the first one.
- **Machine load and the quick suite.** `npm run test:quick` has 20 s test timeouts; with CPU stress or parallel agents running (load average 150 to 850) it fails on timeouts alone. Re-run on a quiet machine before judging a result, and keep CPU-burner experiments out of the same window as verification runs.
- **Wix benefit pools.** The `add-items-to-benefit` endpoint answers an empty 403 for both the API key and the Wix connector, so linking a plan to a service is dashboard-only. The dashboard's "connect plan to service" creates a new PUNCH_CARD pool every time, which is what multiplied sessions.
- **`@node-minify/core` glob override.** While `@opennextjs/cloudflare` is pinned to 1.20.16 (with `@opennextjs/aws` 4.1.15), `package.json` `overrides` forces `@node-minify/core` onto `glob` 14.0.6, which brings `minimatch` 11.0.9 (patched for GHSA-g3hv-75wg-m249 and GHSA-3g3m-2fjr-6pw4); the old nested `glob` 10.5.0 and `minimatch` 9.0.9 were flagged by `npm audit`. `npm run wix:build` and a cookie-bearing request against the built worker pass with it. Remove the override once `@opennextjs/cloudflare` moves past 1.20.16 (a version whose cookie request passes) and `npm audit --audit-level=moderate` stays at 0 without it.
